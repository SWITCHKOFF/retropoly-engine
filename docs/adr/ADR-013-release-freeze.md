# ADR-013 — Release freeze: любая публикация отложена до v0.9.x

- **Статус:** Accepted (2026-11-14)
- **Спринт:** S37–38 (release gate v2), решение после отзыва v0.2.1
- **Связанные документы:** [`../RELEASING.md`](../RELEASING.md),
  [`../plans/sprint_37_38.md`](../plans/sprint_37_38.md),
  [`../../ci/normative_contracts.yaml`](../../ci/normative_contracts.yaml),
  [`../../.github/workflows/release.yml`](../../.github/workflows/release.yml)

## 1. Контекст

Release gate v2, SDK+UI payload и release workflow были реализованы в
S37–38. GitHub Release v0.2.1 был создан автоматически по тегу, но затем
удалён/отозван: публичный релиз должен выпускаться не ранее v0.9.x и
только после того, как maintainer вместе с агентом вручную протестирует
скачанные assets. Текущая версия SDK/UI ещё недостаточно стабильна для
публичного релиза; основная разработка (N64 и дальнейшие итерации)
продолжается.

До этого решения `release.yml` создавал **публичный** GitHub Release
автоматически при push тега `v*`. Это не соответствует желаемому процессу.

## 2. Решение

1. **Любая публикация релизов RetroPolyEngine отложена до v0.9.x** —
   включая v0.2.x, v0.3.0, v0.4.0 и все последующие версии. До v0.9.x
   публичных GitHub Release нет; допускаются только draft-релизы,
   CI-артефакты и локальные сборки.
2. `release.yml` при push тега создаёт только **draft** GitHub Release
   (assets + отчёты gate); публикация — не ранее v0.9.x, вручную после
   приёмки.
3. Перед публикацией обязательна ручная приёмка maintainer + агент:
   скачивание draft-assets, checksums, clean unpack, SDK consumer,
   UI New Project → import → Build → Run, PS1/Saturn `.cue`-проверки.
   Приёмка не снимает freeze: draft остаётся draft до выпуска v0.9.x.
4. GitHub Release и тег `v0.2.1` удалены/отозваны; версия 0.2.1
   остаётся development-версией и не считается публичным релизом.
5. В `ci/normative_contracts.yaml` фиксируется:
   `release_freeze.active: true`, `until: "v0.9.x"`,
   `v0_2_1_release_status: withdrawn`, `auto_publish: false`.
6. Анонсы и метрики релиза не публикуются до v0.9.x.

## 3. Последствия

- Разработка и CI (`build-*`, `tests`, `sdk-package`, `ui-client`,
  release gate) продолжаются без публикации релизов.
- `release.yml` остаётся полезным для проверки release-кандидатов:
  он собирает SDK/UI, запускает gate и загружает assets в draft.
- Публичный GitHub Release появляется только после достижения v0.9.x
  и ручной проверки; до этого draft не публикуется.
- При достижении v0.9.x freeze пересматривается отдельным ADR/обновлением
  политики; статус `released` выставляется только для фактически
  опубликованной версии.

## 4. Альтернативы

| Вариант | Почему отклонён |
|---|---|
| Оставить auto-publish по тегу | Нет ручной приёмки; v0.2.1 уже был опубликован преждевременно |
| Полностью отключить `release.yml` | Теряется воспроизводимый gate и draft-assets для тестирования |
| Публиковать каждый tag как prerelease | Всё равно публично; не соответствует требованию ручной проверки |
