### 1.1. Почему не mupen64plus

mupen64plus (2.5.9/2.6.0) не загружает ROM с libdragon IPL3 r5+:
dynarec падает `Compile at bogus memory address`, pure interpreter не
доходит до user code (mupen64plus-core#1185, открыт на 2026-11-14).
Наш boot-demo использует IPL3 r8/r10-эру — воспроизведено локально.
**ares** загружает такие ROM, но upstream не публикует Linux-бинарь;
**gopher64** загружает, печатает ISViewer-лог и стабильно работает под
Xvfb. Поэтому baseline — gopher64 1.2.1.

## 3. Сборка

### 3.1. Установка toolchain + libdragon (Linux x86_64)

```sh
mkdir -p ~/n64-sdk && cd ~/n64-sdk

# 1) pinned deb (проверка SHA-256)
curl -L -o gcc-toolchain-mips64-x86_64.deb \
  https://github.com/DragonMinded/libdragon/releases/download/toolchain-continuous-prerelease/gcc-toolchain-mips64-x86_64.deb
sha256sum -c /path/to/retro-engine/ci/n64-toolchain.sha256
dpkg-deb -x gcc-toolchain-mips64-x86_64.deb toolchain
export N64_INST="$HOME/n64-sdk/toolchain/opt/libdragon"

# 2) pinned libdragon
git clone https://github.com/DragonMinded/libdragon.git
git -C libdragon checkout e356bf3f56f7afbf7e5246329562f145965cfdfc
make -C libdragon -j"$(nproc)"
make -C libdragon install
make -C libdragon tools-install
export LIBDRAGON_ROOT="$HOME/n64-sdk/libdragon"
```

`make install` ставит `libdragon.a`/`libdragonsys.a`/заголовки в
`$N64_INST/mips64-elf/{lib,include}`; `tools-install` — `n64tool`,
`n64sym`, `n64elfcompress`, `mkdfs`, `dumpdfs` и др. в `$N64_INST/bin`.

### 3.2. Сборка ROM

```sh
cmake --preset n64-release
cmake --build --preset n64-release
```

Артефакты `build/n64-release/src/hal/n64/`:

| Файл | Назначение |
|---|---|
| `hello_n64.z64` | bootable ROM (canonical demo name) |
| `hello_n64.z64.sha256` | SHA-256 (basename, `sha256sum -c`) |
| `hello_n64.map` | linker map |
| `retro_n64.z64` | те же байты (engine name) |
| `retro_n64.elf` | MIPS ELF (debug) |
| `retro_n64.sym` | libdragon symbol table (в ROM TOC) |
| `retro_n64.dfs` | read-only DFS image (`CUBE.MSH`, `TEX0.TEX`, `TRIANGLE.MSH`) |
| `retro_n64.dfs.txt` | `dumpdfs -l` listing |

Reference build S41–42 (2026-11-14): `hello_n64.z64` — 327 680 B
(320 KiB), 2 PT_LOAD, DFS 68 864 B; точный SHA-256 — в
`hello_n64.z64.sha256` (меняется при любом изменении кода/ассетов).

Сборка **проверяет детерминизм mkdfs**: образ создаётся дважды и
сравнивается побайтово (`compare_files`); расхождение — ошибка сборки.

`n64-release` — единственный канонический вход; ручные `cmake -B` с
другими toolchain-файлами не поддерживаются.

### 3.3. Проверка ROM без эмулятора

```sh
python3 scripts/verify_n64_rom.py build/n64-release/src/hal/n64/hello_n64.z64
# ожидается RESULT: PASS, entry 0x80000400, policy=libdragon_ipl3_header_crc_unused
python3 scripts/verify_n64_no_heap.py
# PASS: heap-вызовов нет (src/hal/n64)
```

`verify_n64_rom.py` проверяет N64 magic, entry, title/category/country,
размер ≤ 64 MiB, ELF32 BE MIPS/PT_LOAD на 256-выравнивании, SHA-256; при
ненулевых CRC1/CRC2 — стандартный boot checksum. libdragon IPL3 header
не читает, поэтому нулевые CRC — штатный policy, а не ошибка.

Проверка DFS в ROM:

```sh
"$N64_INST/bin/dumpdfs" -l build/n64-release/src/hal/n64/hello_n64.z64
"$N64_INST/bin/dumpdfs" -e build/n64-release/src/hal/n64/hello_n64.z64 CUBE.MSH \
  | cmp - assets/build/cube.mesh
```

## 4. ROM layout и header

```
0x0000  header 64 B      magic 80 37 12 40, entry 0x80000400, title/category
0x0040  IPL3             libdragon signed bootcode (production)
0x1000+ ELF (256-align)  stripped/compressed ELF32 BE MIPS
...     TOC/symbols      n64tool --toc + retro_n64.sym
...     DFS (16-align)   mkdfs image; dfs_init(DFS_DEFAULT_LOCATION) ищет .dfs
```

Header CRC1/CRC2 = 0: libdragon IPL3 не использует официальный N64
checksum (`libdragon/boot/README.md`). `n64tool` пишет title
`RETRO POLYENGINE`, category `N`, region `E`.

## 5. Boot path S41–42

`main_n64.cpp`:

1. `Platform_Init`:
   - `rpe_n64_core_init`: `debug_init_usblog` + `debug_init_emulog`
     (ISViewer), `timer_init`, `display_init(320×240, 16-bit, 2 buffers)`,
     `rdpq_init`, `joypad_init`, встроенный debug-шрифт;
   - `memory_init`: ledger check + static arenas + MemoryProfiler;
   - `input_init`; `fs_init` (`dfs_init(DFS_DEFAULT_LOCATION)`);
   - `assets_load_boot`: `CUBE.MSH`/`TEX0.TEX` из DFS в asset arena.
2. Self-test идемпотентности: `Init` → `Init` → `Shutdown` → `Init`;
   `rpe_n64_core_shutdown` делает `joypad_close`, `rspq_wait` →
   `rdpq_close` → `display_close`; font освобождается до close.
3. Boot-лог через `Log_Message` → `debugf` → ISViewer/USB; rate limit
   120 строк/с (при переполнении окна печатается счётчик dropped).
4. `Render_Init(320×240)` → main loop:
   `Platform_PumpEvents` (ровно один `joypad_poll`) →
   `Render_BeginFrame` (display_get + rdpq_attach + clear) →
   debug-строки через `rpe_n64_text_print` → `Render_EndFrame`
   (rdpq_detach_show).
5. На экране: `RETROPOLYENGINE N64`, `BOOT OK / S41-42`,
   `VI 320X240 16BPP NTSC`, размеры `CUBE.MSH`/`TEX0.TEX`, memory
   overlay current/peak, состояние pad 1 и frame/time.
6. Heartbeat `frame=… time=…` каждые 300 кадров (~5 с); там же
   asset-load stress: `CUBE.MSH`/`TEX0.TEX` заново читаются в staging и
   освобождаются (`reload=1 staging=0`), что проверяет DFS/арены без
   роста памяти на 10-минутном прогоне.

`hal_render_backend_*` — skeleton: `init` (reference 320×240),
`begin_frame`/`clear`/`end_frame` работают через RDPQ; `draw_triangle`,
`create_texture`, `draw_overlay`, `read_pixels` до S43–44 возвращают
`false` + диагностику. Silent drop запрещён: ядро фиксирует
`RENDER_DIAG_BACKEND_FAIL`, backend пишет предупреждение один раз.

## 6. Memory map и ledger (policy, 4 MiB)

| Регион | Размер | Использование |
|---|---:|---|
| RDRAM base | 4 194 304 B | 4 MiB обязательный минимум |
| CPU stack | 65 536 B | libdragon `STACK_SIZE` = 64 KiB |
| VI framebuffers | 307 200 B | 2 × 320×240 × 16-bit |
| Asset arena | 1 572 864 B | persistent `.mesh`/`.tex` |
| Frame arena | 262 144 B | per-frame scratch (S43–44) |
| Command arena | 131 072 B | bounded RDP command/display-list |
| FS staging | 131 072 B | загрузка файла до парсинга (LIFO/bump) |
| Code/data/SDK reserve | 1 724 416 B | ELF + libdragon + boot-heap |
| **Итого** | **4 194 304 B** | ровно 4 MiB |

`src/hal/n64/n64_memory.h` фиксирует ledger `static_assert`'ами:
engine arenas = 2 MiB, stack = 64 KiB, framebuffer = 300 KiB, reserve
≥ 1 MiB. Runtime `memory_ledger_check()` сверяет `get_memory_size()`
(4/8 MiB) и refuse boot при < 4 MiB.

**Expansion Pak** определяется (`get_memory_size()` ≥ 6 MiB — порог
libdragon `is_memory_expanded`; gopher64 запускается с
`--disable-expansion-pak false` и сообщает 8 MiB), но арены v0.3.0
**не растут**: 8 MiB — reference environment, не требование. `docs`/CI
бюджет — только 4 MiB base.

**Heap запрещён**: `new/delete/malloc/free` не используются в
`src/hal/n64/*`; проверка — `scripts/verify_n64_no_heap.py` (CI).
libdragon внутри использует malloc для DFS-хэндлов/шрифтов/boot-heap —
это входит в `code/data/SDK reserve`, а не в engine-аллокации.
MemoryProfiler регистрирует `n64_asset/frame/command/fs` + stack +
reserve + framebuffers; overlay показывает current/peak в KiB.

## 7. Input mapping (N64 → engine)

Источник — libdragon `joypad`; `Platform_PumpEvents` вызывает
`joypad_poll()` **ровно один раз за кадр**, HAL читает защёлкнутый
снимок 4 портов. Нет контроллера/неподдерживаемое устройство — все
кнопки отпущены, оси 0 (без краша).

| N64 | `INPUT_PAD_*` | Примечание |
|---|---|---|
| D-pad Up/Down/Left/Right | UP/DOWN/LEFT/RIGHT | цифровой |
| A | CROSS | основная кнопка |
| B | CIRCLE | вторая |
| Z | SQUARE | trigger |
| C-Up | TRIANGLE | камера |
| C-Down | SELECT | камера |
| C-Left | L2 | камера/совместимость |
| C-Right | R2 | камера/совместимость |
| L / R | L1 / R1 | shoulder |
| Start | START | |

Оси:

| N64 | `INPUT_AXIS_*` | Диапазон |
|---|---|---|
| stick X/Y | LEFTX / LEFTY | −127..127, deadzone 8 |
| C-stick X/Y | RIGHTX / RIGHTY | −127..127, deadzone 8 |
| analog L/R | L2 / R2 | 0..127 (из 0..255) |

Y-оси инвертируются в SDL-конвенцию (вверх = отрицательное значение).
События подключения/отключения и нажатия логируются (`n64_input`),
rate limit защищает ISViewer от flood'а.

## 8. ROM/DFS-ассеты

DFS — read-only DragonFS (`mkdfs`), образ вставляется `n64tool
--align 16`. Имена — bare UPPERCASE 8.3 (как на PS1/Saturn):

| Файл | Размер | Назначение |
|---|---:|---|
| `CUBE.MSH` | 600 B | `.mesh` v1: 24 вершины, 12 индексов |
| `TEX0.TEX` | 66 068 B | `.tex` v1: 256×256 CI8 + 256×u16 палитра |
| `TRIANGLE.MSH` | 105 B | `.mesh` v1 для следующих демо |

HAL-контракт:

- `FileSystem_LoadFile("CUBE.MSH")` → `FileData`, освобождение только
  `FileSystem_FreeFile`;
- путь нормализуется в UPPERCASE; `/`, `\`, `:`, `..`, пробелы и
  host-пути отвергаются;
- размер проверяется до чтения; файл > 128 KiB (`FS_MAX_FILE_BYTES`)
  отвергается;
- чтение точное: short read = `FS_ERR_READ_FAIL`, без частичного
  результата и без занятой staging-памяти;
- `fs_open/read/close` + `fs_read_range`; `fs_read` за границей файла —
  `FS_ERR_TRUNCATED` без изменения буфера;
- malformed/truncated `.mesh`/`.tex` не оставляют данных в asset arena:
  `mesh_validate_and_load`/`texture_validate_and_load` вызываются под
  marker'ом, при ошибке — rollback.

## 9. Ручной gate (gopher64 1.2.1)

```sh
# 1) скачать pinned gopher64 (не вендорится)
curl -L -o gopher64 \
  https://github.com/gopher64/gopher64/releases/download/v1.2.1/gopher64-linux-x86_64
chmod +x gopher64
# 2) запустить boot-demo
GOPHER64_BIN=$PWD/gopher64 scripts/run_n64.sh
# headless (CI-подобное окружение, без дисплея):
xvfb-run -a -s "-screen 0 800x600x24" \
  env GOPHER64_BIN=$PWD/gopher64 scripts/run_n64.sh

# 10-минутный stress (PASS — `time=600000+ ms`, reload=1 staging=0,
# без ERROR/crash; в headless llvmpipe может занять до ~15 мин wall):
xvfb-run -a -s "-screen 0 800x600x24" \
  timeout -s KILL 900 env GOPHER64_BIN=$PWD/gopher64 scripts/run_n64.sh \
  2>&1 | tee /tmp/n64_stress.log
```

В headless llvmpipe 10 минут N64-времени могут занять больше 10 минут
wall-clock; критерий PASS — `time=600000+ ms` в heartbeat, `reload=1
staging=0`, отсутствие ERROR/crash. Для строгого прогона запускайте
эмулятор без параллельной нагрузки и ждите heartbeat ≥ 600 000 мс.

Чек-лист 60 секунд:

- [x] экран 320×240, тёмно-синий clear `(0,0,32)`, строки
      `BOOT OK / S41-42`, `DFS OK MESH 600 TEX 66068`, `MEM …`;
- [x] в stdout/ISViewer: `boot: … target=n64`, `init/shutdown/init
      self-test OK`, `CUBE.MSH`/`TEX0.TEX` loaded, heartbeat каждые ~5 с;
- [x] controller: нажатия логируются `[n64_input] pad0 press …`;
- [x] 60 с без краша/RSP-crash (gopher64: ≥ 3500 кадров);
- [x] скриншот 320×240 — reference
      `screenshots/n64_boot_s41_42.png`;
- [x] `python3 scripts/verify_n64_rom.py …` — PASS;
- [x] `dumpdfs -l hello_n64.z64` содержит `CUBE.MSH`/`TEX0.TEX`;
- [x] 10-минутный stress без краша/деградации (ручной, non-gating).

## 11. Ограничения v0.3.0 / S41–42

- Нет audio/AI, нет записи на картридж/64DD, нет PAL/480i target.
- Нет RSP/RDP-рендера, Z/TMEM/текстур — S43–44; renderer —
  skeleton (clear + Begin/EndFrame), draw API явно возвращает false.
- Engine overlay (`Render_OverlayText`) на N64 пока не реализован;
  boot-demo рисует текст через C-мост (`rpe_n64_text_print`).
- DFS — только read-only bare-имена, без подкаталогов; staging 128 KiB,
  максимум 4 файла одновременно.
- Expansion Pak определяется, но не расширяет арены; 8 MiB не
  обязателен для v0.3.0.
- N64 SDK/UI-пакет и release notes — S45–46; публикация — после
  release freeze (v0.9.x). Версия проекта остаётся 0.2.1, пока идёт
  development-ветка v0.3.0; bump до 0.3.0 — S45–46 перед draft.
- Windows-сборка экспериментальна (toolchain win64 + `n64tool.exe`);
  CI — Linux.

## 12. Troubleshooting

| Симптом | Причина/решение |
|---|---|
| `N64_INST не задан` | экспортировать `N64_INST` (install-prefix) |
| `N64 toolchain неполон` | нет `n64tool`/`libdragon.a`; выполнить `make install` + `tools-install` |
| `LIBDRAGON_ROOT HEAD=…` | checkout не на pinned commit `e356bf3` |
| `mips64-elf-gcc … не N64 cross-toolchain` | в `N64_INST` лежит host gcc |
| `n64sym: objdump … Нет такого файла` | путь с пробелами; CI/сборка используют relative paths (исправлено в CMake) |
| `DFS image not found` / `DFS=unavailable` | ROM собран без `--align 16 retro_n64.dfs`; проверить `n64tool`-шаг и `dumpdfs -l` |
| `CUBE.MSH not loaded from DFS` | имя/регистр/размер файла; HAL принимает bare UPPERCASE ≤ 128 KiB |
| `command arena overflow` | >128 KiB команд за кадр; явная ошибка, не silent drop (S43–44 добавит реальные RDP-команды) |
| RSP crash при повторном `rdpq_init` | `rspq_wait` перед `rdpq_close` (реализовано) |
| Чёрный экран в mupen64plus | известный баг mupen64plus#1185; использовать gopher64 |
| `sha256sum -c` не находит файл | запускать из каталога артефактов (в `.sha256` basename) |
