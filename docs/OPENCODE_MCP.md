# MCP-серверы OpenCode: Context7 и TestSprite

> Конфигурация: [`opencode.json`](../opencode.json).
> Скрипт управления ключами:
> [`scripts/opencode-mcp-secrets.sh`](../scripts/opencode-mcp-secrets.sh).

## Что подключено

| Сервер | Транспорт | Назначение | Ключ |
| --- | --- | --- | --- |
| `context7` | Remote (`https://mcp.context7.com/mcp`) | Актуальная документация библиотек и API | Необязателен (без ключа работает с меньшим лимитом) |
| `testsprite` | Local (`npx @testsprite/testsprite-mcp@latest`) | Автоматические QA-прогоны TestSprite | Обязателен |

Оба сервера подключены в проектном `opencode.json`. Проверка:

```sh
opencode mcp list
```

Ожидаемый результат:

```text
✓ context7    connected
✓ testsprite  connected
```

В OpenCode то же самое показывает команда `/mcps`.

## Куда вставлять ключи

Ключи **не хранятся** в `opencode.json`, в репозитории, в истории shell или
в глобальном окружении пользователя. Они лежат в отдельном каталоге вне git:

```text
~/.config/opencode/secrets/
├── context7_api_key      # 0600
└── testsprite_api_key    # 0600
```

Каталог имеет права `0700`, файлы — `0600`, владелец — текущий пользователь.

### Безопасный способ (рекомендуется)

```sh
cd /path/to/RetroPolyEngine
./scripts/opencode-mcp-secrets.sh set
```

Скрипт по очереди попросит ключи. Ввод скрыт (`read -s`), поэтому ключ не
попадает в историю команд и не отображается на экране. Для Context7 можно
просто нажать Enter — сервер работает и без ключа.

После вставки проверьте состояние:

```sh
./scripts/opencode-mcp-secrets.sh status
```

Скрипт покажет только факт наличия ключа, его права, владельца и размер.
Сами значения он не выводит никогда.

Затем в OpenCode выполните `/reload` (или перезапустите `opencode`), чтобы
MCP-серверы перечитали файлы.

### Ручной способ

Если ключ нужно положить вручную, создайте файл без завершающего перевода
строки. Не передавайте ключ аргументом команды — он попадёт в историю shell:

```sh
install -d -m 700 ~/.config/opencode/secrets
install -m 600 /dev/null ~/.config/opencode/secrets/testsprite_api_key
read -rsp 'TestSprite API key: ' RPE_KEY
printf '%s' "$RPE_KEY" > ~/.config/opencode/secrets/testsprite_api_key
unset RPE_KEY
```

Не используйте `echo` (он добавляет `\n`) и не редактируйте файл обычным
редактором, который добавляет newline в конец: OpenCode передаёт содержимое
файла в заголовок/переменную окружения как есть. Проверка:

```sh
./scripts/opencode-mcp-secrets.sh status
```

## Как это устроено

В `opencode.json` вместо самих ключей стоят ссылки на файлы:

```jsonc
"headers": {
  "CONTEXT7_API_KEY": "{file:~/.config/opencode/secrets/context7_api_key}"
}
```

```jsonc
"environment": {
  "API_KEY": "{file:~/.config/opencode/secrets/testsprite_api_key}"
}
```

OpenCode читает файл при загрузке конфигурации и подставляет содержимое.
Сами ключи в конфигурации, git-диффе и истории команд не появляются.

### Что защищает такая схема

- **Другие пользователи системы** не могут прочитать ключи: каталог `0700`,
  файлы `0600`.
- **Случайный коммит** исключён: каталог находится вне репозитория, а в
  `opencode.json` только путь.
- **История shell и логи** не содержат ключ: ввод скрыт, ключ не передаётся
  аргументом командной строки.
- **Подмена пути**: скрипт отказывается работать, если каталог секретов или
  файл ключа является символической ссылкой, и проверяет владельца.
- **Атомарная запись**: ключ пишется во временный файл в том же каталоге и
  затем переименовывается, поэтому сбой не оставит частично записанный ключ.
- **Контроль формата**: скрипт отклоняет управляющие символы и пробельные
  символы в конце ключа.

### Что важно понимать

- Файлы ключей — обычный текст с правами `0600`. Это стандартная практика для
  локальных секретов, но она не защищает от процессов, работающих от вашего же
  пользователя, и от root. Для защиты от кражи диска используйте шифрование
  домашнего каталога (LUKS/FileVault/BitLocker).
- TestSprite MCP — локальный процесс. Ключ передаётся ему через переменную
  окружения `API_KEY` только на время работы этого процесса. В глобальное
  окружение shell ключ не экспортируется.
- Context7 — удалённый сервер. Ключ передаётся в HTTP-заголовке
  `CONTEXT7_API_KEY` только этому серверу.

## Ротация и удаление

```sh
# Заменить ключ (ввод скрыт)
./scripts/opencode-mcp-secrets.sh set testsprite

# Удалить оба ключа
./scripts/opencode-mcp-secrets.sh clear

# Удалить только Context7
./scripts/opencode-mcp-secrets.sh clear context7
```

После отзыва ключа в личном кабинете удалите локальную копию и выполните
`/reload` в OpenCode.

## Требования и ограничения

- Для `testsprite` используется Node.js 22 из пользовательской установки:
  `~/.local/opt/node22` → `node-v22.23.4-linux-x64`. Команда MCP явно
  добавляет `~/.local/opt/node22/bin` в `PATH`, поэтому TestSprite не зависит
  от системного Node.js.
- Системный `/usr/bin/node` остался версии 20.20.2 (NodeSource 20.x) и не
  затрагивался. Новые терминалы получают Node 22 через `~/.bashrc` и
  `~/.profile` (`~/.local/bin`). Проверка: `node -v` → `v22.23.4`.
- Если OpenCode был запущен до изменения `PATH`, его встроенный shell может
  показывать старый `node -v` (20.20.2). На TestSprite это не влияет: команда
  MCP явно добавляет Node 22 в `PATH`. Новые терминалы используют Node 22.
- Чтобы обновить пользовательский Node 22, распакуйте новый дистрибутив в
  `~/.local/opt`, переключите симлинк `~/.local/opt/node22` и обновите
  симлинки `node`/`npm`/`npx`/`corepack` в `~/.local/bin`.
- `@latest` в команде TestSprite означает, что при первом запуске `npx` может
  скачать свежую версию пакета. Если нужна воспроизводимость, замените её на
  закреплённую версию, например `@testsprite/testsprite-mcp@0.0.48`.
- Первый запуск `testsprite` может быть долгим: `npx` скачивает пакет, а сервер
  выполняет первичную инициализацию.

## Диагностика

```sh
# Состояние ключей и прав
./scripts/opencode-mcp-secrets.sh status

# Состояние MCP-серверов
opencode mcp list

# Полный список серверов и авторизация в TUI
# /mcps
```

Если `testsprite` подключён, но инструменты возвращают ошибку авторизации,
ключ не вставлен или вставлен с newline/пробелом в конце — проверьте
`status` и перезапишите ключ через `set`.
