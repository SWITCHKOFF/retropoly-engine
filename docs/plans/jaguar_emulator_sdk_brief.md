# Бриф: выбор эмулятора и SDK для RetroPolyEngine (Jaguar / Jaguar CD)

> **Назначение:** единый чек-лист для сравнения эмуляторов и SDK перед
> решением о Jaguar v0.4.0. Это не оценка конкретного кандидата, а набор
> вопросов, на которые кандидат должен ответить **доказательствами**.
> Связанные документы: [`jaguar_legal_audit_v2.md`](jaguar_legal_audit_v2.md),
> [`jaguar_legal_hold.md`](jaguar_legal_hold.md).
> **Заполненные ответы:** [`jaguar_emulator_sdk_answers.md`](jaguar_emulator_sdk_answers.md).
>
> **Статус:** **DEFERRED — «до лучших времён»** + LEGAL HOLD (ADR-016);
> бриф заполнен, но S47–52 не активируются, Jaguar-код/toolchain/ROM/CD/
> payload не создаются. Старт — только по явному личному разрешению
> maintainer начать Jaguar; снятие hold само по себе не активирует.
>
> **Объём:** 183 вопроса в 12 секциях (A–L).

## 0. Как пользоваться

Для каждого вопроса:

- **Ответ:** `Да` / `Нет` / `Частично` / `Не знаю`.
- **Доказательство:** ссылка на LICENSE/README/файл/коммит/тест/issue.
- Ответ без доказательства считается `Не знаю`.

Теги:

| Тег | Значение |
|---|---|
| **[M]** | Must-have. Ответ `Нет` — кандидат не проходит gate (или требует письменного исключения). |
| **[S]** | Should-have. Влияет на взвешенную оценку, не блокирует сам по себе. |
| **[A]** | Acceptable/optional. Полезно, но не обязательно. |
| **[X]** | Must-not. Ответ `Да` — red flag/нарушение; кандидат отклоняется или требует юридического исключения. |
| **[?]** | Нужно доказательство/ручная проверка; сам по себе не требование. |

**Главное правило:** сначала юридический gate (A), затем эмулятор (B–D),
затем SDK (E–H), затем интеграция (I–J), затем поддержка (K–L).

## Правила решения

1. **Любой `[X]` = «Да»** — кандидат отклоняется или требует письменного
   юридического исключения.
2. **Любой `[M]` = «Нет»** — кандидат не проходит gate; можно рассматривать
   только как experimental/optional.
3. **`[M]` = «Частично»** — условный допуск с явным планом закрытия.
4. **`[S]`** — взвешенная оценка; не блокирует, но влияет на выбор.
5. **Юридический gate (A) — первый.** Нельзя компенсировать хорошей
   техникой плохую лицензию.
6. **CD gate (G) — отдельный.** Эмулятор может быть сильным, а SDK — не
   уметь CD; это разные компоненты.
7. **Для MIT-движка:** GPL-эмулятор допустим только как external
   process; GPL/LGPL runtime в target — нет.

## Быстрые red flags

Если хотя бы один пункт ниже — «Да», кандидат, скорее всего, не подходит:

- GPL/LGPL-код линкуется в engine/UI/runtime.
- В SDK/репозитории лежат Atari BIOS/ROM/проприетарные headers.
- Эмулятор требует BIOS/ROM в нашем payload.
- Нет headless/CLI/exit codes/screenshot/hash — нельзя автоматизировать.
- Нет 68000 toolchain/HAL/CD authoring — это не SDK для движка.
- Нет лицензии/SPDX/источника — нельзя оценить риск.
- Телеметрия/сеть/аккаунт/админ-права без необходимости.
- Закрытый бинарник без публичной лицензии — нельзя вендорить.

## Что считать «хорошим» кандидатом

- **Эмулятор:** GPL-3.0 как external process; headless/CLI; CD; HLE;
  deterministic screenshots/hash; input scripting; save states; known
  issues; active maintenance; BIOS policy без бандлинга.
- **SDK:** MIT/BSD/Unlicense; 68000 C + GPU/DSP asm; ROM header/checksum;
  deterministic build; CMake; no-heap runtime; 2 MiB ledger; CD authoring
  или чистый cartridge-only профиль; no Atari headers/BIOS.
- **Интеграция:** external emulator adapter; SDK provider через
  `find_program`; license manifest/CI; release payload без эмулятора и
  BIOS.
