# hello_triangle

Минимальный полный пример RetroPolyEngine (веха M4 «Hello Triangle PC»,
docs/plans/sprint_11_12.md): ECS-сцена из слоя `game/`, меш из `.mesh`,
текстура из `.tex`, fps-камера WASD+мышь, цикл по контракту §10
(60 Гц тики, рендер каждого кадра).

## Что видно

Текстурированный треугольник в центре экрана: рендер-фреймбуфер 320×240
(PS1-стиль, nearest-апскейл в окно 1280×960), камера стоит в (0, 0, 5) и
смотрит на origin (fov 60°, near 1, far 100). На треугольнике — текстура
из пайплайна ассетов (256×256, `.tex` + палитра). Окрас фона и «клетка»
текстуры зависят от `assets/build/*` (генерируются конвертером при сборке).

## Сборка

```sh
cmake --preset pc-release
cmake --build --preset pc-release
# бинарь: build/pc-release/game/hello_triangle
```

Debug-вариант для повседневной работы — пресет `pc-debug`, бинарь
`build/pc-debug/game/hello_triangle`. Ассеты (`assets/build/*.mesh/*.tex`)
генерируются автоматически на этапе сборки (CMake вызывает
`tools/asset_converter` / `scripts/make_source_assets.py`).

## Запуск (интерактив)

```sh
./build/pc-release/game/hello_triangle
```

Запускается окно 1280×960; мышь захватывается (relative mode, курсор
невидим). Закрыть окно или **ESC** — выход.

### Управление

| Клавиши              | Действие                                  |
|----------------------|-------------------------------------------|
| `W` / `↑`            | вперёд (куда смотрит камера)              |
| `S` / `↓`            | назад                                     |
| `D` / `→`            | вправо                                    |
| `A` / `←`            | влево                                     |
| `Space`              | вверх (мировая вертикаль)                 |
| `Shift` (L/R)        | вниз                                      |
| мышь                 | поворот камеры (yaw/pitch, сенса 0.005 rad/px); pitch клампится перед вырождением look_at |

Диагонали нормированы (скорость одинаковая во всех 8 направлениях);
скорость полёта — 3 единицы/секунду.

## Bench-режим

```sh
./build/pc-release/game/hello_triangle <секунды>   # например 60
```

Камера фиксирована (дефолтная поза, ввод игнорируется), сессия
длится заданное число секунд, после чего процесс завершается с кодом 0.
FPS-лог в file-sink'е Logger'а (`retro_engine.log` в текущем каталоге):
по завершении каждого секундного окна — `fps=N (окно M)`, в конце — итог
(кадры/мс/среднее fps). Окно 1 обычно завышено (прогрев GL/Mesa); для
замеров ориентируйтесь на среднее и устойчивые окна.

## Протокол замера W1 (≥ 60 FPS)

Полка W1 снимается так:

1. Сборка релиз-пресетом: `cmake --preset pc-release && cmake --build --preset pc-release`.
2. Замер: `./build/pc-release/game/hello_triangle 60` (60 секунд).
3. Среднее fps из итоговой строки лога; окружение фиксируется снапшотом
   `docs/benchmarks/reference_environment.yaml` (ос/цпу/гпу/драйвер/
   компилятор/build/resolution/vsync/measurement_seconds/git_revision/
   asset_set_sha256).

Замер 2026-11-05 (снапшот окружения — в yaml): среднее **482.79 fps**
(28996 кадров за 60058 мс), полка «≥ 60 FPS» выполнена с запасом ≈ ×8.
Сравнение только внутри одного снапшота yaml (числа без окружения
недействительны); в stdout FPS не печатается — только file-sink Logger'а.

## Визуальная регрессия (golden)

Кадр примера защищён эталоном: тест `HelloTriangleGolden.DefaultSceneView`
(пресеты `pc-debug-render`/`pc-release-render`, `ctest --preset pc-debug-render`)
строит ту же сцену общим `scene.h` и сравнивает снимок кадра по FNV-хэшу с
`tests/visual/reference/hello_triangle_default.bin` (бюджет фолбэка 128 px —
tie-breaking растеризатора вне GL-спецификации). Регенерация эталона — только
осознанным rebase: `RENDER_GOLDEN_REBASE=1` после намеренного изменения рендера,
с обоснованием в журнале.

Пути ассетов не зависят от каталога запуска: CMake подаёт определение
`HT_ASSET_DIR=<корень>/assets/build` на этапе компиляции; дефолт
`HT_ASSET_DIR="."` в scene.h — только для ручного прогона из корня
репозитория.
